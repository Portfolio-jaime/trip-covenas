# Setting up a Google Service Account for the dashboard

The dashboard's Lambda needs a way to read your Google Sheet without a
human logging in. Google's answer to this is a **Service Account**: a
robot identity with its own email address (something like
`covenas-dashboard-reader@your-project.iam.gserviceaccount.com`). You
create it once, download a "key" file for it, and share your Google Sheet
with that email address — the same way you'd share it with a person, just
give it **Viewer** access.

This doc assumes you've never used the Google Cloud Console before. Every
step is spelled out.

---

## 1. Create a Google Cloud project (or reuse one)

A "project" is just a container Google uses to group things together. If
you already have any Google Cloud project you're happy to reuse, skip to
step 2.

1. Go to <https://console.cloud.google.com/> and sign in with the Google
   account that owns (or has edit access to) the trip's Google Sheet.
2. If this is your first time here, Google may ask you to accept its
   Terms of Service — accept them.
3. At the top of the page, click the project dropdown (it's next to the
   "Google Cloud" logo — it might say "Select a project" or show an
   existing project name).
4. Click **New Project** (top-right of the dialog that opens).
5. Give it a name, e.g. `covenas-dashboard`. Leave "Location" as-is.
6. Click **Create**. Wait a few seconds for the notification bell (top
   right) to say the project was created, then use the project dropdown
   again to switch into it.

You will not be charged for any of this — nothing below touches billing.

## 2. Enable the Google Sheets API

APIs are off by default per-project; you have to turn on the ones you
need.

1. With your project selected, go to
   <https://console.cloud.google.com/apis/library/sheets.googleapis.com>
   (this link takes you straight to the Sheets API page).
2. Click **Enable**.
3. Wait for the page to confirm it's enabled (a few seconds).

## 3. Create the Service Account

1. Go to
   <https://console.cloud.google.com/iam-admin/serviceaccounts>
   (make sure the project selector at the top still shows your project).
2. Click **+ Create Service Account** near the top.
3. **Service account name**: something recognizable, e.g.
   `covenas-dashboard-reader`. Google will auto-fill a "Service account
   ID" below it — you can leave that as generated.
4. Click **Create and Continue**.
5. On the next screen ("Grant this service account access to project"):
   **leave it empty and click Continue.** The service account does not
   need any project-level role — it will only ever have access to the one
   Google Sheet you explicitly share with it in step 5 below. This is the
   "no special roles" principle: least privilege.
6. On the next screen ("Grant users access to this service account"):
   leave it empty too, click **Done**.

You'll land back on the Service Accounts list, with your new account in
it. Note its email address — it'll look like:

```
covenas-dashboard-reader@covenas-dashboard-123456.iam.gserviceaccount.com
```

(the numbers after your project name are auto-generated by Google — yours
will differ). You'll need this exact email in step 5.

## 4. Generate a JSON key for the Service Account

This key file is what lets the Lambda "log in" as the service account.
Treat it like a password — never commit it to git, never paste it into a
chat, never email it.

1. On the Service Accounts list (same page as above), click the service
   account you just created.
2. Go to the **Keys** tab.
3. Click **Add Key** → **Create new key**.
4. Choose **JSON** (should be selected by default) and click **Create**.
5. Your browser will download a `.json` file automatically — something
   like `covenas-dashboard-123456-a1b2c3d4e5f6.json`. This is the only
   copy Google gives you a friendly way to get; if you lose it, you'll
   need to create a new key (old ones can be deleted from the same Keys
   tab).
6. Move that downloaded file somewhere outside this repo (e.g.
   `~/secrets/covenas-dashboard-key.json`) — even though `.gitignore` in
   this repo is set up to ignore obviously credential-named `.json`
   files, the safest habit is to just never let it land inside the repo
   folder at all.

You'll hand this file's contents to `aws ssm put-parameter` per
`infra/README.md` — Terraform itself never sees or stores it.

## 5. Share the Google Sheet with the Service Account

This is the step that actually grants read access to your trip data.

1. Open the live `Gastos_Covenas` Google Sheet in your browser (the one
   in your family's Google Drive, not the local `.xlsx` file in this
   repo).
2. Click the green **Share** button (top-right).
3. In the "Add people and groups" box, paste the service account's email
   address from step 3 (the `...@...iam.gserviceaccount.com` one).
4. Google may show a warning like "this person doesn't have a Google
   Workspace account" or similar — that's expected and fine, service
   accounts aren't real Google Workspace users.
5. Set its permission level to **Viewer** (not Editor, not Commenter) —
   the dashboard only ever reads the sheet, it should never be able to
   change it.
6. Untick "Notify people" if it's ticked (a service account can't read
   email anyway).
7. Click **Share** / **Send**.

## 6. Find the Sheet ID

The Lambda also needs to know *which* sheet to read — that's the
`google_spreadsheet_id` Terraform variable.

Look at the sheet's URL in your browser:

```
https://docs.google.com/spreadsheets/d/1AbCdEfGhIjKlMnOpQrStUvWxYz1234567890/edit#gid=0
                                        └──────────────── this part ────────────────┘
```

The long string of letters/numbers between `/d/` and `/edit` is the Sheet
ID. Copy it — you'll pass it as `-var google_spreadsheet_id=...` when
running `terraform plan`/`apply`.

- [ ] Sheets API enabled on that project
- [ ] Service account created, with **no** project roles granted
- [ ] JSON key downloaded and saved *outside* this repo
- [ ] Sheet shared with the service account's email as **Viewer**
- [ ] Sheet ID copied from the URL
